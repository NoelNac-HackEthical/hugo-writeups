{{/* layouts/shortcodes/escalade-intro.html */}} {{- $user := .Get "user" | default "www-data" -}} {{- $md := ` Une fois le premier accès obtenu en tant que %s, tu disposes d’une session utilisateur sur la machine. **L’escalade de privilèges consiste à identifier une commande, un script, un binaire ou un service exécuté avec des privilèges supérieurs que l’utilisateur courant peut influencer afin d’obtenir une session root.** Comme dans tous mes writeups, et conformément à la recette {{< recette "privilege-escalation-linux" >}}, cette phase commence par une énumération méthodique du système. Lorsque cela est possible, tu peux lancer pspy64 dans une deuxième session. L’outil reste ainsi actif pendant les vérifications manuelles et permet d’observer les processus, scripts et tâches planifiées exécutés périodiquement, notamment par root. Les premières vérifications portent ensuite sur les éléments suivants : - les droits sudo avec sudo -l, afin d’identifier les commandes que l’utilisateur courant peut exécuter avec les privilèges d’un autre utilisateur ou de root - le contexte de l’utilisateur courant avec id, whoami et l’inspection de ses groupes - les fichiers et répertoires intéressants dans /home, /opt, /usr/local et les répertoires propres à l’application - les Linux capabilities avec getcap -r / 2>/dev/null - les binaires SUID avec find / -perm -4000 -type f 2>/dev/null, puis, si nécessaire, avec python3 suid3num.py - les tâches cron avec cat /etc/crontab ainsi que l’inspection des répertoires /etc/cron.* - les services et ports accessibles uniquement en local avec ss -tulpn ou netstat -tulpn Les commandes, binaires et configurations inhabituels sont ensuite analysés afin de déterminer s’ils peuvent être détournés. Les binaires disposant de droits particuliers peuvent notamment être comparés aux techniques documentées sur GTFOBins. **L’objectif n’est pas de tester des exploits au hasard, mais de comprendre le fonctionnement de la machine afin d’identifier une faiblesse logique, une permission excessive ou une mauvaise configuration exploitable.** Si cette énumération manuelle ne révèle aucune piste suffisamment claire, tu peux alors utiliser un outil plus exhaustif comme linpeas.sh. Son résultat doit toutefois être considéré comme une aide à l’analyse : les éléments signalés doivent toujours être vérifiés manuellement avant de tenter leur exploitation. ` -}} {{- $content := printf $md $user -}} {{ .Page.RenderString $content }}
